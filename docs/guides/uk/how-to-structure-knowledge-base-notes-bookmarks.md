# Як структурувати базу знань із нотаток і закладок: PARA vs Zettelkasten vs 20 плоских папок (2026)

> **Коротка відповідь:** Найефективніший спосіб структурувати базу знань із розрізнених нотаток і браузерних закладок — перейти на **плоску таксономію з 20 фіксованих папок** у форматі локального Markdown із YAML-метаданими та `[[вікі-посиланнями]]`. На відміну від глибоких дерев папок чи ручного Zettelkasten, пласка структура витримує масовий імпорт 1 000+ посилань без хаосу, працює офлайн в Obsidian і дає високу точність пошуку для ШІ-агентів через MCP та NotebookLM.

Майже кожен розробник, дослідник або підприємець рано чи пізно стикається з «кладовищем закладок»: сотні збережених посилань у Chrome/Safari, хаотичні нотатки в Apple Notes, чернетки в Notion та переслані повідомлення в месенджерах. Щойно архів перевищує 300 записів, ручне сортування ламається — знайти потрібну статтю стає довше, ніж заново загуглити тему.

У цьому посібнику ми розберемо чотири головні архітектури особистої бази знань (PKB), дамо готову схему 20 папок, шаблон Markdown-нотатки та покроковий план міграції хаосу у впорядкований Obsidian Vault за 15 хвилин.

## 1. Чому більшість баз знань і закладок перетворюються на хаос

Незалежно від обраної програми, неструктурований архів завжди впирається в чотири системні проблеми:

- **Глибокі дерева папок (4+ рівнів вкладеності):** Кожне нове посилання вимагає складного рішення. Стаття про ШІ в медицині одночасно підходить у `Технології`, `Здоров'я` та `Дослідження` — у результаті виникають дублікати або файли губляться.
- **Сирі дампи закладок (`bookmarks.html`):** Браузер зберігає лише заголовок і крихкий URL. Якщо блог видаляють або домен змінюється, знання втрачаються назавжди.
- **Вибух неконтрольованих тегів:** Ручні теги швидко розростаються у синоніми (`#ai`, `#ШІ`, `#llm`, `#machine-learning`), через що фільтрація перестає бути надійною.
- **Перевантаження контексту ШІ-моделей:** Згодовувати агентам сирий JSON занадто дорого. У реальних бенчмарках формат TOON зменшує витрати контексту з `25 093` до `15 880` токенів (`-36.7%` – `-45%`).

Вирішення полягає не в черговому закритому хмарному додатку, а в чіткій, передбачуваній файловій архітектурі на базі відкритого Markdown.

## 2. Порівняння: PARA vs Zettelkasten vs Johnny.Decimal vs 20 плоских папок

Кожна популярна методологія проєктувалася під різний сценарій роботи. Обирайте ту, що відповідає вашим реальним джерелам (нотатки + закладки + PDF + відео).

| Критерій | PARA (Projects, Areas, Resources, Archives) | Zettelkasten (Атомарні картки) | Johnny.Decimal (Числова ієрархія) | 20 плоских папок (ScrapLibra) |
| :--- | :--- | :--- | :--- | :--- |
| **Глибина папок** | 3–4 рівні | 0–1 рівень (лише граф) | 3 жорсткі числові рівні | **1 плоский рівень (20 доменів)** |
| **Масовий імпорт 500+ закладок** | Повільно (ручний розбір під проєкти) | Дуже повільно (ручне переписування) | Середньо (ручна нумерація) | **Швидко (автоматична маршрутизація)** |
| **Обслуговування на тиждень** | 30–60 хв (перенесення в архів) | 45–90 хв (створення зв'язків) | 20–40 хв (підтримка індексу) | **< 5 хв (нуль реорганізації)** |
| **Ризик «сирітських» нотаток** | Середній (папка Resources роздувається) | Високий без щоденної дисципліни | Низький | **Мінімальний (YAML + авто-вікілінки)** |
| **Точність RAG / ШІ-агентів** | Середня (теми розкидані по проєктах) | Висока для есе, слабка для лінків | Середня | **Висока (доменна ізоляція + MCP)** |
| **Незалежність від платформи** | Висока (якщо Markdown) | Висока (Obsidian / plain text) | Висока | **100% локальний Markdown + YAML `.zip`** |
| **Найкраще підходить для** | Активних клієнтських проєктів | Написання книг і дисертацій | Корпоративних регламентів | **Нотаток, закладок, PDF та ШІ-пошуку** |

Детальний архітектурний розбір читайте у [повному гайді ScrapLibra по Second Brain](https://scraplibra.com/uk/guides/second-brain-obsidian-para-zettelkasten/).

### Де дає збій PARA
PARA чудово працює для завдань із дедлайном, але 80% браузерних закладок, довідників та ідей не прив'язані до поточного проєкту. Вони осідають у `3_Resources`, яка за два місяці перетворюється на черговий нерозібраний звалище-інбокс.

### Де дає збій чистий Zettelkasten
Метод Лумана ідеальний для авторських досліджень із нуля, але провалюється при спробі оцифрувати 1 500 наявних закладок, конспектів YouTube та PDF-документів. Переписувати кожне посилання вручну в атомарні картки надто довго — більшість користувачів здаються на другому тижні.

### Чому 20 плоских папок перемагають для нотаток і закладок
Плоска таксономія розділяє **фізичне зберігання** та **смислові зв'язки**:
- **20 папок задають стабільні домени.** Кожна нотатка лежить рівно в одній папці першого рівня (`01_Technology_AI` … `20_Reference_Archive`).
- **YAML frontmatter тримає метадані.** Оригінальний URL, дата, тип джерела та нормалізовані теги завжди машинозчитувані.
- **`[[Вікі-посилання]]` будують граф зв'язків.** Нотатка з `01_Technology_AI` спокійно посилається на `04_Finance_Investing` без копіювання файлів.

Повну специфікацію дивіться у посібнику [Таксономія 20 плоских папок](https://scraplibra.com/uk/guides/20-folder-flat-taxonomy/).

### Стандартна анатомія Markdown-нотатки з YAML
Кожен файл у базі знань повинен мати єдину шапку — це робить базу готовою для Obsidian Dataview, Python-скриптів і ШІ-агентів:

```markdown
---
title: "Оптимізація пам'яті ШІ-агентів через MCP та TOON"
source_url: "https://scraplibra.com/uk/how-it-works/mcp-toon-agent-memory/"
domain: "01_Technology_AI"
type: "technical-guide"
created: "2026-11-27"
tags: [mcp, toon, obsidian, pkm]
---

# Оптимізація пам'яті ШІ-агентів через MCP та TOON

## Головні тези
- Локальні Markdown-файли захищають закладки від зникнення сторінок (link rot).
- Формат TOON скорочує витрати токенів ШІ на 36.7%–45% порівняно з JSON.
- Плоскі доменні папки прискорюють пошук навіть при 5 000+ нотаток.

## Пов'язані нотатки
- [[Таксономія 20 плоских папок]]
- [[Міграція браузерних закладок в Obsidian]]
```

Детальніше про структуру файлів читайте в розділі [Анатомія Obsidian Markdown](https://scraplibra.com/uk/how-it-works/obsidian-markdown-anatomy/).

## 4. Покроковий план: як навести лад у 1 000+ нотатках і закладках за 15 хвилин

1. **Експортуйте закладки браузера:** збережіть файл `bookmarks.html` із Chrome, Arc, Brave, Safari або Firefox (покрокова інструкція — у [гайдi по системі браузерних закладок](https://scraplibra.com/uk/guides/browser-bookmarks-system/)).
2. **Зберіть старі нотатки в одну папку:** вивантажте Markdown/CSV із Notion, Pocket, Raindrop або Evernote.
3. **Відфільтруйте сміття та биті посилання до обробки:** не витрачайте час і токени на 404-сторінки, дублікати та порожні нотатки.
4. **Розкладіть валідні матеріали у 20 папок із YAML та `[[вікі-посиланнями]]`.**
5. **Завантажте локальний `.zip`-архів і відкрийте його в Obsidian** як готову базу знань.

## 5. Підключення бази знань до ШІ-агентів (MCP + TOON) та NotebookLM

Найбільша цінність структурованої бази — можливість ставити їй запитання напряму з Claude Desktop, Cursor або Gemini CLI. Через [віддалений MCP-сервер ScrapLibra](https://scraplibra.com/uk/mcp-docs/) ваша бібліотека підключається однією командою:

```bash
gemini mcp add --transport http 'scrap-libra' \
  'https://telelibra-cloud-222446907059.europe-west1.run.app/mcp'
```

Замість громіздкого JSON сервер передає записи у компактному форматі **TOON (Token-Oriented Object Notation)**. На вибірці зі 100 нотаток це зменшує споживання контексту з `25 093` до `15 880` токенів (`-36.7%` – `-45%`), роблячи відповіді ШІ швидшими й точнішими ([детальний бенчмарк MCP + TOON](https://scraplibra.com/uk/how-it-works/mcp-toon-agent-memory/)).

А завдяки плоским доменним папкам ви можете одним кліком завантажити конкретний розділ (наприклад, `05_Science_Research`) у **Google NotebookLM**, щоб отримати аудіо-підсумок або дослідницький бриф строго за вашими джерелами.

## 7. Часті запитання (FAQ)

### Скільки папок оптимально мати в особистій базі знань?
Оптимальний діапазон — **15–20 плоских папок першого рівня**. Менше 10 папок перетворюються на переповнені кошики, а понад 30 — створюють втому від вибору під час кожного збереження.

### Що краще для закладок браузера: PARA чи Zettelkasten?
Жоден із них не розрахований на масовий імпорт посилань. Використовуйте **20 плоских папок** для надійного зберігання та поєднуйте нотатки через `[[вікі-посилання]]` у стилі Zettelkasten.

### Чи можна перенести старі закладки з Pocket, Raindrop або Notion в Obsidian?
Так. Експортуйте дані в HTML/CSV/Markdown, приберіть неробочі URL і перетворіть кожен корисний матеріал на чистий `.md`-файл із YAML-метаданими.

### Навіщо YAML frontmatter, якщо є папки та теги?
Файл фізично може лежати лише в одній папці, тоді як YAML зберігає `source_url`, дату, тип документа та список тегів для миттєвої фільтрації без дублювання нотаток.

### Чи залишаються мої нотатки у моїй власності?
Так, на 100%. Уся структура експортується у стандартні текстові Markdown-файли (`.zip`), які відкриваються офлайн в Obsidian, VS Code або будь-якому текстовому редакторі.
